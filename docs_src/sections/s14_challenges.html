Challenges Faced and Solutions Attempted

ChallengeSolution
Most of the team had never built a web application.Picked Flask + server-rendered HTML instead of React; built one complete page together as a template, then copied the pattern for every other page.
Slab billing was hard to get right by hand (boundaries, open-ended last slab, decimals).Wrote the formula as a small pure function, checked it with hand-calculated cases at slab edges and with decimal units (UT-01 to UT-06).
Making sure readings never go backwards, even if someone bypasses the form.Two layers: instant JavaScript check in the form, and BEFORE INSERT triggers in the database that abort the transaction.
Old bills changing when the admin edits a tariff.Store a snapshot of charges and bill items on each bill (deliberate denormalisation, explained in the DBMS design).
Showing electricity (kWh), water (kL) and gas (SCM) in one chart was misleading.Comparison charts use rupees; usage history shows one chart per utility in its own unit.
Realistic demo data for six months.Seed script reads customers from a CSV and generates readings with seasonal variation, then produces bills and payments using the real billing code.
Tests interfering with each other through a shared database.Each test gets a fresh database file in a temporary folder.
Doing both the DBMS and SEPM projects without double work.One code base and one schema; the DBMS report focuses on schema, normalisation and SQL objects, and this report focuses on process and engineering.
