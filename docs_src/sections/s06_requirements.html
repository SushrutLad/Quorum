Requirements Specification

Requirements were gathered from (a) the DBMS project brief, (b) study of real electricity/water bills and published slab tariffs, (c) existing utility self-service portals, and (d) team brainstorming sessions with role-play of each user type. The full IEEE-830-style SRS is provided separately in 02_Requirements/SRS.pdf; the key requirements are summarised here.

Prioritisation of requirements

We used the MoSCoW method. Must requirements make up the minimum system that solves the core problem (readings → bills → payments, plus access control and complaints). Should requirements add important value but the system still works without them. Could items are added if time allows, and Won't (now) items are out of scope for this semester. Implementation followed this order, so every Must requirement was completed before mid-semester.
