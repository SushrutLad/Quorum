Technology Stack and Justification

We deliberately chose the simplest stack that still meets all requirements, so every team member can read, run and explain all of the code.

LayerTechnologyWhy we chose itAlternatives considered
LanguagePython 3.10+Already taught in earlier semesters; readable; large ecosystem.Java, PHP
Web frameworkFlask 3Very small: a page is one function with a URL. No build step. Includes password hashing (Werkzeug) and templates (Jinja2).Django (too much to learn), Node/Express
DatabaseSQLite 3Built into Python, single file, zero setup, but still supports constraints, triggers, views and indexes for the DBMS course. Schema is standard SQL and can be moved to MySQL later.MySQL (needs a server), MongoDB (not relational)
FrontendHTML + Jinja2 templates + one CSS fileServer-rendered pages; no JavaScript framework to learn; one page per feature.React (needs Node build tools, steeper learning curve)
ChartsChart.js 4 (one file, bundled locally)One script tag; works offline.D3.js (complex), Google Charts (needs internet)
Testingpytest + Flask test clientSimple test functions; the test client drives real pages against a fresh database.unittest, Selenium
Version controlGit + GitHubShared code, history as contribution evidence.–
DiagramsMermaid (text-based), draw.ioDiagrams stored as text next to the code; easy to update.StarUML
Technology stack

Only one third-party package (Flask) is needed to run the app. pytest is used only for the tests.
