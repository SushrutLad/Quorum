Architecture diagram

EUMS uses a three-tier (layered) client–server architecture with the Model-View-Controller idea: templates are the view, Flask route functions are the controller, and the SQLite tables with billing.py form the model. The browser sends ordinary HTTP GET/POST requests (HTML forms); the server returns finished HTML pages. One small JSON endpoint gives the previous meter reading to the reading form.

Module description

File / moduleResponsibility
app.pyCreates the Flask app, loads configuration, registers the two route groups, login/logout pages, error pages, and template helpers (money, date formatting).
auth.pylogin_required(*roles) decorator: redirects to login if not signed in, returns 403 if the role is not allowed.
db.pyOpens one SQLite connection per request (foreign keys on, rows as dictionaries) and closes it afterwards; query() helper.
billing.pyPure function calculate_bill() for slab pricing (unit tested) and generate_bill(), which reads the tariff and inserts the bill and bill items.
routes_staff.pyAdmin and employee pages: dashboard, customers, connections, meter readings, billing, payments, complaints, outages, tariffs, employees, reports.
routes_customer.pyCustomer portal: dashboard, connections, bills, pay, usage history, complaints, outages, profile, notifications. Every query is filtered by the logged-in customer.
schema.sqlAll tables, constraints, indexes, triggers and views.
seed.pyCreates the database and loads demo data (24 customers from sample_data/customers.csv, 6 months of readings, bills, payments, complaints, outages).
templates/, static/Jinja2 HTML pages (one per feature), one CSS file, and a small Chart.js helper.
tests/pytest unit tests (billing) and functional tests (whole app with a fresh database per test).
