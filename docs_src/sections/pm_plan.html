Effort and schedule estimation (Basic COCOMO)

The current build has {{ '{:,}'.format(loc) }} lines of code, so the finished system is estimated at about {{ kloc }} KLOC. It is a small project built by a small team with familiar requirements, so we use the organic mode (a = 2.4, b = 1.05, c = 2.5, d = 0.38):

Effort E = 2.4 × ({{ kloc }})1.05 = {{ '%.1f'|format(effort) }} person-months     Duration D = 2.5 × E0.38 = {{ '%.1f'|format(duration) }} months     Staff = E / D ≈ {{ '%.1f'|format(people) }} full-time people

Four students working part-time (about 6 hours a week each, roughly 0.15 of a full-time person) give about 0.6 full-time equivalents over 3.5 months, which is about 2 person-months. That is much less than the COCOMO estimate. The gap is expected: COCOMO was calibrated on industrial projects that include full documentation, formal reviews and maintenance, and it overestimates very small projects that use a high-level framework. We use it as an upper bound and manage the gap through MoSCoW scoping (Should/Could features can be dropped without breaking the system).
